# Request: deploy the GDPR Fine Calculator web part to the App Catalog

One page, for whoever owns the tenant App Catalog. Everything below is
checkable before anything is installed.

## What is being asked

Upload one file, `gdpr-fine-calculator.sppkg`, to the tenant App Catalog and
approve it. That is the whole request. No tenant setting changes, no permission
grant, no service principal, no API access consent.

## What it is

A no framework SharePoint Framework web part that benchmarks a turnover figure
against published GDPR enforcement decisions. Someone types their organisation's
annual turnover, optionally picks what went wrong, and gets three numbers: what
comparable organisations actually paid, the realistic range around that, and the
Art. 83 statutory ceiling. It is a benchmark drawn from published enforcement
practice, not a prediction and not legal advice, and the page says so.

The underlying data is 355 published enforcement decisions where the fined
organisation's turnover is known, taken from the public GDPR enforcement tracker
with turnover attached separately from company filings and national registers.

## Why it needs the App Catalog and not something simpler

The same tool exists as a single HTML file. It cannot be used in SharePoint,
because SharePoint refuses to render `.aspx` or `.html` from a document library
unless custom script is enabled on the site, and custom script is off by default
and reverts within 24 hours when switched on per site. Classic user-created
pages also go read-only for all tenants on 1 October 2028, so that route has a
known end date. The App Catalog is the supported path and the only one that
lasts.

## The security questions, answered up front

**No outbound network access.** All 355 records are compiled into the package.
The web part makes no fetch, no XHR, no script tag with an external `src`, no
web font and no image request. This was verified by running the identical build
with every network request intercepted: zero were attempted. It works on a
machine with no internet access.

**No data leaves the browser.** The turnover someone types is used in
arithmetic in that browser and is never transmitted. Nothing is written to
SharePoint, to a list, to local storage or to a log. There is no telemetry.

**No custom script dependency.** The manifest declares
`requiresCustomScript: false` and that is accurate: no `eval`, no injected
script tags, no dynamically constructed code. The tenant setting that governs
scripts in document libraries is irrelevant to this package.

**No permissions requested.** The package requests no Microsoft Graph scopes and
no SharePoint API permissions. `webApiPermissionRequests` is absent from the
solution. There is nothing for an admin to consent to beyond the deployment
itself.

**No third party code.** No React, no charting library, no npm runtime
dependency. The chart is hand written inline SVG. The only packages involved are
Microsoft's own SPFx libraries, which the toolchain supplies.

**Source is reviewable.** Four hand written TypeScript files plus one generated
data file. It can be read in an hour by anyone who wants to, and the data file
is regenerated by a script from a published source rather than hand edited.

## How it was built and checked

It targets **SPFx 1.23.2**, the current general release, and builds with the
supported Heft toolchain on Node 22. To be straight about the state it is in:
the `.sppkg` is produced by whoever runs the build, from this source, with
Microsoft's own generator and toolchain. Nothing has been compiled by a
third party and handed over as a binary.

Checks already run against the source:

- TypeScript compiles clean under `strict`, with `noUnusedLocals`,
  `noUnusedParameters` and `noImplicitReturns`, against an ES5 library target.
- ESLint passes with zero problems under Microsoft's own
  `@microsoft/eslint-config-spfx` profile. Not zero errors: zero problems.
- The logic was run side by side with the reference implementation across 420
  combinations of input and produced identical output in every one, including
  the chart geometry to the decimal place.
- Colour choices were validated for colour vision deficiency and contrast rather
  than picked by eye.

Size: about 1,450 lines of commented TypeScript across four files, plus a
generated data file holding the 355 records.

## What deployment involves

1. Upload `gdpr-fine-calculator.sppkg` to **Apps for SharePoint** in the App
   Catalog.
2. Approve the deployment when prompted. It can be scoped to specific sites or
   made available tenant wide, whichever the reviewer prefers.
3. The web part then appears in the toolbox under **Advanced** on modern pages.

Removal is the same in reverse and leaves nothing behind.

## If the answer is no

That is a reasonable answer, and there is a fallback that needs nothing from the
App Catalog: the same calculator hosted externally and shown through the Embed
web part, which needs only a site collection administrator to allow the domain
under Site Settings, HTML Field Security. That route puts the content outside
the tenant, which is exactly the trade being avoided by asking for the package
instead.
